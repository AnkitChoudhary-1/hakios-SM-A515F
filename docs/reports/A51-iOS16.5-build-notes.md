### Initial boot behavior

The selected recipe uses `ufs=2`, `root_apfs=ufs_darwin`, `ufs_write=0`, `var_store=0`, touch enabled, GPU/Wi-Fi disabled, three framebuffer buffers, and `loader_return_after=300`. The kernel and helper filesystems are embedded in the recovery payload; the Apple root filesystem and cryptexes are read from the existing darwin partition. Persistence is disabled, and this is a timed diagnostic session.

The diagnostic image enters the resident USB command loop **if USB initialization succeeds**. It then accepts `fastboot oem run`. If USB initialization fails, the source falls through to an automatic one-shot attempt with the embedded kernel and then resets. The standalone image omits the USB flag and attempts the embedded kernel automatically. A kernel hang or earlier firmware failure may prevent normal timed return; the USB diagnostic path completed one timed run on this phone; the standalone path remains untested.

In the first measured run, the 61-second capture still showed the Apple logo and the 123-second capture showed Control Center. The owner confirmed the home screen appeared during the session. This establishes UI rendering by about two minutes for this recipe, not an exact or guaranteed home-screen boot time. The requested kernel window was five minutes.

## Reproduction in the existing builder

These commands target the already prepared WSL checkout. They are not a complete clean-machine setup; the prior IPSW extraction, Theos SDK, toolchains, Python venv, and applied Mu-Silicium changes are inputs. `source-state.json` records commits and tracked local patches. Preserve those patches.

- `scripts/build-loader.sh` records the initial identity generation and loader build. It intentionally refuses to overwrite an existing identity or loader. For an incremental rebuild in the current checkout, use `make loader` there.
- `scripts/build-userland.sh` records the initial hardlink-tree preparation and userland build. It intentionally refuses to replace already prepared extraction directories. For an incremental rebuild, use the same exports recorded in that script and run `userland/build.sh` from the checkout. Avoid changing permissions or editing files in the shared hardlink extraction trees.
- `scripts/rebuild_uefi.py` performs the successful incremental venv-based firmware build and preserves patches. Avoid the wrapper that removes and reapplies them.
- `scripts/prepare_system.py` extracts and validates the three IPSW components and assembles the Apple system region on the host. It checks complete known SHA-256 values and refuses to overwrite an existing system image. Large extraction intermediates remain under `D:\A51-iOS16.5-build\work\ipsw-images`.
- `scripts/prepare_boot.py` packages the current kernel/loader/helper/firmware/DTB and validates both recovery variants. It replaces the prepared package files and manifests, so retain an older manifest before intentionally rebuilding packages.
- `scripts/install_a51.py --check` validates the current phone and complete local backups without writing phone storage.
- `scripts/run_diagnostic.py --prepare` prepares a fresh-epoch RAM payload without issuing phone commands.

Invoke Linux Python scripts with `wsl -d A51-KernelBuilder -- python3 /mnt/c/Users/Ankit/Documents/Codex/2026-11-21/hi-2/outputs/scripts/<script>.py`; invoke Windows scripts with `python.exe` from this workspace. Shell build scripts require `bash`. Record new image hashes, commands, results, and observed failures here after each change. Keep `phone_boot_tested` and home-screen verification distinct from build checks.
