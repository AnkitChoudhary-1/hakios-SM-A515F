For each change, add a stable phase-specific log entry naming files, reason, validation, limits and rollback. Use `run.py` for consequential execution. It passes arrays directly to subprocess with no shell, avoiding PowerShell/Bash quoting ambiguity. Scripts are host-specific: Windows Python inventory imports Windows project paths; Linux Python acquisition/build capture/QEMU use `/opt` and `/mnt/c`. The retained-image audit and layout validator map recorded Windows/WSL paths for both hosts; a fresh libfdt cross-check requires WSL, while its readback runs on either host.

Host audit changes must preserve binary bounds, original-image associations and explicit uncertainty. Linux reserved-memory `size` uses root size cells, while `alignment` uses root address cells. Base RAM comes only from root memory children; unapplied overlay memory and `__local_fixups__` metadata cannot be counted as merged memory/effects. Revision-interval matches are conditional. Keep `safe_for_loader_placement=false`; mathematical gaps and Android header addresses do not establish available memory. Preserve both archived Phase 1 roadmap copies and the completed bundle when updating current state/roadmap.

The [version 1 layout guide](PAYLOAD-LAYOUT.md) defines strict schema/provenance, unsigned 64-bit bounds, full effective/padded extents, separate roles, input/slice hashes, ownership and replay. All 92 guards passed on each host; one synthetic case was accepted and 21 A51 cases were rejected with required diagnostics. Version 1 has no runtime ownership importer. Do not reinterpret caller `runtime_observation` labels, declared high banks or static gaps as physical ownership. A new runtime ownership importer would be new implementation with its own evidence and guards. Documentation-only corrections require link/state checks; they do not require another build or QEMU run when tested code and inputs are unchanged.

## Future kernel/loader edits

The [source-trace guide](SOURCE-TRACE.md) records the version 1 specification, 28 sources/40 excerpts, three base FDTs/22 symbols, six retained tools/82 indexed files and 35 passed guards per host. A specification-only excerpt correction was verified by fresh capture and both host replays; executable scripts remained unchanged. Replay deliberately uses the retained specification and original-byte inputs with matching tools. Restore a specific recorded revision in a compatible project root when investigating historical behavior, rather than weakening hashes or treating nested snapshots as standalone projects.

The Android source root has no Git metadata; its commit is recorded lineage, and individual hashes pin inspected bytes. Preserve source distinctions when editing documentation: absent configuration is unknown, KASLR's saved zeros are not original entry observations, FDT export is conditional and can follow Linux seed removal, and disabled DEBUG_FS cannot expose the inspected memblock/memsize paths. Legacy PSCI/reset/log declarations do not prove current firmware capabilities, active callbacks, payload-log retrieval or return. Changing Android configuration or programming device reset/log resources is outside this host milestone.

Make an experimental checkout separate from this reproducible Phase 1 baseline, pinned to the same starting commit. Future source pins and recorded patches must be deliberate. Current `verify-sources.py` rejects modified common/dependency sources; do not disable it silently. Update the port's verification strategy to record an identified patch set or commit.

Durable common drivers belong in upstream `drivers/<subsystem>/` with `drivers/map` and configuration definitions. `xnu/sync-drivers.sh` copies them into `xnu-src`; `tools/hakios-config.py` controls which are built. Durable changes to Apple files belong in the HakiOS patch/overlay path, not only in generated BUILD or generated XNU files. Read `xnu/export.sh` and upstream porting instructions before exporting. A raw diff against Apple's HEAD includes upstream HakiOS modifications; distinguish the existing overlay from your new patch.

Configuration inputs live in `configs/` and external SoC/device repositories. `.config`, `MASTER.hakios` and `hakios.drivers.h` are generated. Editing only `.config` is overwritten by the next `make defconfig`. Runtime boot arguments and driver compilation are separate controls; a driver may be built and remain inactive.

The EFI loader source is `xnuloader/loader.c`; placeholder `identity.h` is generated. The minimal program is `userland/src/hello.c`. A Samsung experimental loader will need its own verified entry/CPU/memory design; copying this EFI application or MTK boot chain is not sufficient. Keep QEMU, loader-only device probes and full XNU device experiments as separately evidenced milestones.

Phase 2's retained-image audit, libfdt cross-check, host layout validator, retained-source trace and host/QEMU loader prototype are implemented. The Linux-exported live FDT and root capture are verified in [LIVE-OBSERVATIONS.md](LIVE-OBSERVATIONS.md). Read [LOADER-PROTOTYPE.md](LOADER-PROTOTYPE.md) before changing the tested interfaces. Follow LOADER-DESIGN.md to resolve original firmware fixups, actual bootloader/entry state, dynamic/secure/runtime ownership, platform transitions and a new payload's device log/return mechanism before configuring an A51 adapter. Prototype fuel cannot preempt a callback, and CPU fault/device watchdog handling is still planned. The upstream QEMU destination `0xF0000000` overlaps declared modem memory and is excluded from an A51 design. This prototype's separate QEMU address also establishes no A51 placement. Header addresses are historical metadata, not known-safe XNU placement. Measured runtime extents and state transitions still require evidence before coding a device jump. Source Linux drivers are references for register/protocol/power behavior; their binaries and kernel APIs are not directly reusable in XNU.

## Review and rollback

Review changes against their previous version and the implementation log. Restore a specific script/package/configuration revision if needed and rerun the affected host check. Build or kernel changes need the clean rebuild procedure and fresh QEMU evidence; layout/documentation changes do not require rebuilding unchanged kernel artifacts. Preserve failed attempts and prior manifests, and replay older evidence with matching script revisions in a compatible project root. Do not delete backups or replace originals with experimental artifacts. Neither Phase 1 scripts nor its documentation should include an executable phone-flashing step.

The documentation covers the implemented baseline and known porting entry points. It cannot predescribe every future driver; extend it alongside each implementation, including interfaces, invariants, register sources and hardware tests.
